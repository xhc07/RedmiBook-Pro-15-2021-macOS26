# 实现说明：我们改了什么、为什么

本仓库在上游（同机型 EFI + WhateverXe）基础上做了 4 处改动。

## 1. 电池适配器：`SSDT-ADPX`

### 问题

`SMCBatteryManager` 启动时要求**同时**找到电池（`PNP0C0A`）**和**电源适配器（`ACPI0003`）：

```cpp
if (!findBatteries() || !findACAdapters()) {  // 两者缺一就整体放弃
    IOLog("failed to find batteries or adapters!");
    return false;
}
```

本机 DSDT 只有电池，没有 `ACPI0003`，于是驱动直接退出 → 没有电量、没有充电状态。

### 方案

新建 `SSDT-ADPX`，发布一个 `ACPI0003` 设备，通过 EC 的 `ACIN` 位读取适配器状态：

```asl
Device (ADPX)
{
    Name (_HID, "ACPI0003")
    Name (_UID, 1)
    OperationRegion (ERMX, SystemMemory, 0xFE0B0300, 0xFF)  // EC RAM 窗口
    Field (ERMX, ByteAcc, NoLock, Preserve) { ..., ACIN, 1, ... }
    Method (_PSR, 0, NotSerialized) { Return (ACIN) }
}
```

### 结果

- 电量、充放电状态正常
- 插拔电源即时刷新（`ExternalConnected` 实时变化）
- 交替搭配：`ACPIBatteryManager` 停用，避免两套驱动冲突

### 注意

另一个方案（`ACPIBatteryManager`）也能显示电量，但**没有充电状态**，且睡眠行为不同；
我们两种都试过（见 docs/04），最终选择 ADPX + SMCBatteryManager。

## 2. Fn 亮度键：`SSDT-BRTN`

### 问题

本机的 Fn 亮度键**不经过 PS2 也不经过 HID**，而是在 EC 里触发 ACPI 查询
`_Q15` / `_Q16`。macOS 侧收不到任何按键事件。

### 方案

1. 用 ACPI Patch 把 DSDT 里的 `_Q15`/`_Q16` 重命名为 `XQ15`/`XQ16`
2. 新增 `SSDT-BRTN` 在 `HEC` 设备下重新定义 `_Q15`/`_Q16`，先调用原方法，
   再向显示设备发通知：

```asl
Method (_Q15, 0, NotSerialized)   // 亮度 -
{
    XQ15()
    Notify (\_SB.PC00.GFX0.DD02, 0x86)
}
Method (_Q16, 0, NotSerialized)   // 亮度 +
{
    XQ16()
    Notify (\_SB.PC00.GFX0.DD02, 0x87)
}
```

3. `BrightnessKeys.kext` 把 ACPI 通知 `0x86`/`0x87` 转成亮度键事件

### 结果

- 大多数场景可用
- 偶尔无响应（EC 上报时序），属于部分可用

## 3. 亮度下限：`Patches/ours/`（对 WhateverXe 的源码改动）

### 问题

WhateverXe 的背光重映射是线性的：苹果亮度值 0 对应占空比 0 → **屏幕全黑**。
把滑块拉到最低会直接黑屏，只能靠手电筒找路径或盲按亮度键。

### 方案

在 `wrapTGLRegisterWrite` 处理 `0xC8258`（背光占空比）时，把苹果的亮度值重映射到
`[floor, hw]` 区间：

```cpp
const uint32_t floor = hw / 16;                       // 6.25%
uint32_t scaled = floor + (uint64_t)value * (hw - floor) / donor;
if (scaled > hw) scaled = hw;
if (scaled < floor) scaled = floor;
```

### 结果

- 最低亮度 6.25%，肉眼几乎全黑但不黑屏
- 滑块全程无死区、无档位合并
- 实测映射：`0/230/390/710 → 6.25/7.46/8.31/9.99%`

详见 [docs/06-亮度调优.md](06-亮度调优.md)。

## 4. softsleep 背光修复（源码改动，未并入预编译 kext）

### 问题

补丁 02 的 softsleep 在唤醒时这样开背光：

```cpp
const uint32_t want = on ? ((pp & 1) ? (pp | 4U) : pp) : (pp & ~4U);
```

`wrapTGLEnterWake()` 在**面板电源就绪之前**执行，此时 `PP_CONTROL` 的 bit0（面板电源）还是 0，
于是 `want == pp`（什么都不写）；而调用方又把 `tglSoftSleepBacklightOff` 无条件清零，
**导致背光永远不会被重新使能**。

### 方案

```cpp
// 1) 唤醒时无条件置背光使能位
const uint32_t want = on ? (pp | 4U) : (pp & ~4U);

// 2) 在 donor 自己写 PP_CONTROL 打开面板电源时补置 bit2
if (reg == 0xC7204 && tglSoftSleepBacklightOff && (value & 1U)) {
    value |= 4U;
    tglSoftSleepBacklightOff = false;
    tglSoftSleepRecord(2, 0, value);
}
```

### 结果

- 短时间（约 10 秒）的睡眠后唤醒，背光能自动恢复
- 长时间后系统仍会进入挂死状态（与睡眠缺陷叠加，见 docs/05）

> 该改动在 `Patches/ours/` 中，**未并入** `EFI/` 中预编译的 kext。

## 5. 显示睡眠：softsleep + 背光修复（2026-11-18 实测通过）

### 5.1 为什么需要 softsleep

本机内屏（TL156MDMP01）**无法通过完整链路重训**。不加 `-wex-tgl-edp-softsleep` 时，
显示器睡眠唤醒会走"重训 → 重新点屏"路径，本机在此路径上 WindowServer 报
`Display not ready`，120 秒后看门狗 panic（实测 3 次：23:38 / 23:47 / 23:53）。

加上 `-wex-tgl-edp-softsleep` 后，显示器睡眠只关背光、保留链路，唤醒只做
`FB0: Partial modeset by updating scaler`，不重训。

### 5.2 背光不恢复的 bug 与修复

softsleep 原实现：

```cpp
const uint32_t want = on ? ((pp & 1) ? (pp | 4U) : pp) : (pp & ~4U);
```

`wrapTGLEnterWake()` 在面板电源（`PP_CONTROL` bit0）就绪**之前**执行，
此时 `pp & 1 == 0` → `want == pp` → **不写背光使能位**；而调用方又把
`tglSoftSleepBacklightOff` 无条件清零 → **永不重试**。

修复（`Patches/ours/`）：

```cpp
// 1) 唤醒时无条件置背光使能
const uint32_t want = on ? (pp | 4U) : (pp & ~4U);
// 2) donor 自己写 PP_CONTROL 打开面板电源时补置 bit2
if (reg == 0xC7204 && tglSoftSleepBacklightOff && (value & 1U)) {
    value |= 4U; tglSoftSleepBacklightOff = false;
    tglSoftSleepRecord(2, 0, value);
}
```

### 5.3 实测证据（`ioreg` 中的 softsleep 记录）

| 记录 | 含义 | PP_CONTROL |
|---|---|---|
| `TGLSoftSleep1` | 关闭背光 | `0x67 → 0x63`（bit2 清零）✅ |
| `TGLSoftSleep2` | **恢复背光** | `0x63 → 0x67`（bit2 置位）✅ |

现象：熄屏后背光灭（用灯照仍可见画面，属正常），唤醒后背光自动恢复。

### 5.4 配置要求

```
boot-args 必须包含: -wex-tgl-edp-softsleep
kext 必须包含上述背光修复（v0.2.1 起）
```

## 6. 我们**没有**改的部分

- 4 个 eDP 补丁（01–04）来自同机型仓库，原样使用（见 `Patches/third-party/`）
- 亮度重映射的「读硬件周期」逻辑来自补丁 03
- 其余 kext 全部使用上游发布版
