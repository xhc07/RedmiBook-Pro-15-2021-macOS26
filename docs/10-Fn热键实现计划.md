## 二、Fn+F6/F7/F8 实测映射（已确认）

方法：SSDT 里让三个查询分别 `Notify(DD02, 0x86)`（增强）或 `0x87`（降低），看亮度方向。

| 按键 | 触发查询 | CWMI 参数 n | 功能 | 实测 |
|---|---|---|---|---|
| **Fn+F6** | `_Q2B` | 1 | 投屏（Win+P） | ✅ 变亮（我们发 0x86） |
| **Fn+F7** | `_Q66` | 2 | 截图 | ✅ 变暗（我们发 0x87） |
| **Fn+F8** | `_Q08` | 3 | 任务视图 | ✅ 变亮（我们发 0x86） |

> ACPI 标准：**0x86 = Increase Brightness，0x87 = Decrease Brightness**。

## 三、技术原理（触发链）

```
按键
 └─ EC 产生查询字节
      └─ ACPI 执行对应 _Qxx（在厂商 SSDT 第 21 张，不是 DSDT！）
           └─ \_SB.PC00.WMID.QV20(n)
                ├─ EVFN = n（写入共享内存 XGNS）
                └─ Notify(WMID, 0x20)
                     ├─ Windows: wmiacpi.sys → _WED(0x20) → WMI 事件 → OSD 服务
                     └─ macOS:   无 WMI 栈 → 通知被丢弃（所以我们之前"看不到"）
```

### 关键 ACPI 事实

| 项目 | 值 |
|---|---|
| 热键表 | `21_SSDT_XMCC1806.bin`（OEM ID `XMCC`，Table ID `XMCC1806`，6384 字节） |
| WMI 设备 | `\_SB.PC00.WMID`，`_HID = PNP0C14`，`_UID = "XAPe"` |
| 事件 GUID | `46C93E13-EE9B-4262-8488-563BCA757FEF`（事件 0x20） |
| 共享内存 | `OperationRegion (XGNS, SystemMemory, 0x40AA2000, 0x2A)` |
| 字段 | 偏移 12 = `EVFN`；偏移 18+ = `MWBU`（payload） |
| payload | 4 字节小端 u32 = `EVTY | EVFU<<8 | EVD1<<16 | EVD2<<24` |
| `QV20` | `EVFN = Arg0; Notify (WMID, 0x20)` |

### EC 查询 → n 对照（来自 SSDT 21）

```
_Q2B→1  _Q66→2  _Q08→3  _Q10→4  _QB2→5（还操作 KBBL）
_Q19→6  _Q23→7  _Q94→8  _Q95→9  _Q25→0x10
_Q2A→0x11 _Q26→0x12 _Q27→0x13 _Q28→0x14 _Q29→0x15
_Q24→0x16 _Q2C→0x18 _Q2D→0x19 _Q2E→0x1A
```

### Linux redmi-wmi keymap（同 GUID，已进上游内核）

| payload | 含义 |
|---|---|
| `0x00010101` | 切换显示/投屏 |
| `0x00000201` | 区域截图 |
| `0x00000301` | 任务视图 |
| `0x00001b01`/`0x00011b01` | 打开设置 |
| `0x00001a01` | 刷新率切换 |
| `0x00011801`/`0x00011901` | AI 助手 |
| `0x00010a01` | G Command Center |
| `0x00011101`–`0x00011501` | F13–F17 |
| `0x00000501` 等 | 键盘背光（忽略） |
| `0x00011601`–`0x00041601` | 性能模式（忽略） |
| `0x00000701`/`0x00010701` | Fn Lock（忽略） |

## 四、已验证 / 已排除（避免重复劳动）

| 假设 | 结论 | 证据 |
|---|---|---|
| 热键写 EC RAM（0xFE0B0300） | ❌ | Windows 下按 F6/F7/F8（含按住 10s）256 字节快照无变化 |
| 热键是 HID 事件 | ❌ | macOS 两轮抓取零事件，无厂商页 0xFF00 |
| 热键在 DSDT 的 `_Qxx` | ❌ | DSDT 只有 10 个查询（电池/盖子/热区） |
| 热键在厂商 SSDT 的 `_Qxx` | ✅ | SSDT 21 里 `_Q2B/_Q66/_Q08` → `QV20(1/2/3)` |
| macOS 是否派发 SSDT 的 `_Qxx` | ✅ **会** | 重定义后按键改变亮度 |
| `0xFE0B0000` 前 16 字节是事件队列 | ❌ | 固件轨迹流，不按键也在变 |
| `SMA2`（0xFE0B0A00）是事件邮箱 | ❌ | 四份快照全 0 |
| 官方 OSD 内核驱动读 EC | ❌ | `OSDServiceDaemon.sys` 只导入 `ZwOpenKey/ZwSetValueKey` |

**踩过的坑（重要）**：
1. kext 缺 `KMOD_EXPLICIT_DECL` → 没有 `_kmod_info` → 内核拒绝加载
2. kext 缺 `registerService()` → 不进 IORegistry → 守护进程匹配不到
3. `IONameMatch` 要用 `_HID` 的值（`MIFS0001`），不是 ACPI 名字（`HKEY`）
4. ACPI 通知码：`0x86`=增强亮度、`0x87`=降低（方向搞反导致一轮测试白做）

**运行时证据**：`ioreg -l -c MIFSKeys` 显示 `EventCount=6 / LastEvent=3`，
`/tmp/mifskeysd.log` 显示 `event 3 → spawn open ok`。

## 五、实现方案（已完成，保留作设计记录）

### 5.1 架构

```
按 F6/F7/F8 → EC 查询 → 我们 SSDT 的 _Qxx
   → Notify(HKEY, 1/2/3)          ← HKEY 是自建假 ACPI 设备
   → MIFSKeys.kext（匹配 HKEY，message() 收通知）
   → IODataQueue（内核→用户态，零轮询）
   → mifskeysd（阻塞等待）→ CGEventPost 注入快捷键
```

### 5.2 组件清单

| 组件 | 内容 | 行数 |
|---|---|---|
| `SSDT-KEYS.dsl` | 建 `Device(HKEY){_HID="MIFS0001"}`；三个 `_Qxx` → `Notify(HKEY,1/2/3)`，**不碰亮度** | ~50 |
| `MIFSKeys.kext` | 匹配 ACPI 设备；`message()` 收 `kIOACPIMessageDeviceNotification`；写 IODataQueue；提供 user client | ~250 |
| `mifskeysd` | 映射队列 + `IODataQueueWaitForAvailableData` 阻塞；`CGEventPost` | ~100 |

### 5.3 动作映射

| code | 动作 | 实现 |
|---|---|---|
| 1（F6） | 投屏/切换显示 | `Cmd+F1` 镜像 |
| 2（F7） | 区域截图 | `Cmd+Shift+4` |
| 3（F8） | 任务视图 | `F3` / `Ctrl+Up` |

### 5.4 关键细节（避坑）

1. ACPI Patch 必须限定：`TableSignature=SSDT` + `OemTableId=XMCC1806` + `Count=1`
2. DSDT 没有 `_Q2B/_Q66/_Q08` → 只作用于厂商 SSDT，安全
3. `External(...XQ2B, MethodObj)` 必须声明，否则运行时找不到
4. HKEY 名字要唯一（`HKEY` / `_HID "MIFS0001"`）
5. kext 匹配用 `IOPropertyMatch`（name=HKEY）；先用 `ioreg -p IOACPIPlane` 确认设备可见

Scope (\_SB) { Device (HKEY) { Name (_HID, "MIFS0001") Name (_UID, One) } }
Scope (\_SB.PC00.LPCB.H_EC) {
    Method (_Q2B, 0) { XQ2B (); Notify (\_SB.HKEY, 1) }   // F6 投屏
    Method (_Q66, 0) { XQ66 (); Notify (\_SB.HKEY, 2) }   // F7 截图

### kext 关键点

```cpp
bool MIFSKeys::start(IOService *provider) {
    if (!IOService::start(provider)) return false;
    setProperty("MIFSKeysReady", kOSBooleanTrue);
    setProperty("EventCount", 0, 32);
    setProperty("LastEvent",  0, 32);
    registerService();          // 必须：否则用户态匹配不到
    return true;
}
IOReturn MIFSKeys::message(UInt32 type, IOService *provider, void *argument) {
    if (type == kIOACPIMessageDeviceNotification) {
        UInt32 code = argument ? *reinterpret_cast<UInt32 *>(argument) : 0;
        fCount++; setProperty("EventCount", fCount, 32);
        setProperty("LastEvent", code, 32);
        return kIOReturnSuccess;
    }
    return IOService::message(type, provider, argument);
}
KMOD_EXPLICIT_DECL(org.mifs.MIFSKeys, "1.0.0", _start, _stop)   // 必须：生成 _kmod_info
```

## 七、开机亮度自动跳高（已解决，2026-11-18）

**现象**：关机前调低 → 开机后自动跳高（最多两次，目标约 0.88）。

**排查**：写了亮度记录器（LaunchDaemon，200ms 采样 `/var/log/brightness.log`），
抓到 `uptime 54s → 0.75`、`uptime 90s → 0.8799`。

**根因**：NVRAM 残留旧驱动变量 `nmintelfb-brightness = 88`（0.88），恒定不更新；
Apple 的 `backlight-level` 正常，但残留值在开机后被恢复。

**修复**：

```bash
sudo nvram -d nmintelfb-brightness
```

**验证**：连续两次重启，开机亮度 = 关机前值（0.20 / 0.625），无跳变。

**说明**：改的是 NVRAM（固件变量），不是 EFI/系统/驱动；NVRAM 非易失，
所以重启与完全关机行为一致。

**已固化**：README §3.4、`docs/04 §I`、`docs/08 §6.5`、`Tools/ai-install.sh` 第 6 步。
