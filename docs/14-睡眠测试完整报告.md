## 四、实验时间线（全部）

### 阶段 1：早期 S3 路线（2026-11-19 前）

| # | 方案 | 结果 |
|---|---|---|
| 1 | 原生 S3 | 关机 |
| 2 | `_S3` 参数 5→7 | 卡死 |
| 3 | GPRW + XPRW 改名 | 无变化 |
| 4 | S0ix（SSDT-DEEPIDLE + S0ixStandby） | `IOPMDeepIdleSupported=Yes` 但 `deep_idle_count=0`（macOS 仍选 S3） |
| 5 | 移除电池 SSDT | 同样 panic |
| 6 | 全套 pmset + 关闭重负载 | 同样 panic |
| 7 | `-wex-noaccel` | **能睡能醒**（108 秒），但无加速、背光不恢复 |
| 8 | `-wex-tgl-hold-render-wake` | WindowServer 挂死 |
| 9 | 作者原版组合 | 失败 |

**结论**：加速器是睡眠阻塞点；但去掉加速就失去意义。

### 阶段 2：DMC 固件（2026-11-19 晚）

依据上游 issue #157 中 @Aqpcet 的方案。

| 步骤 | 内容 |
|---|---|
| 固件 | `tgl_dmc_ver2_12.bin`（19,760 字节，主 payload @0x310，4,460 dword） |
| Hook | `hwInitializeCState`（0x43972）+ `systemDidWake`（0x2897A） |
| 上传 | payload → 0x80000，回读校验 |

**第一版实现有误**：MMIO 表全部写 0（等于禁用所有 DMC 事件处理器）。

| 结果 | 说明 |
|---|---|
| 死锁修复 | ✅ 睡眠不再死锁，能睡能醒 |
| 新问题 | ❌ 唤醒后 RENDER 域 forcewake 超时 → panic |

### 阶段 3：S0ix + 隐藏 S3（2026-11-19 23:03）

**关键洞察**：macOS 优先用 S3，所以要**把 S3 藏起来**。

| 配置 | 值 |
|---|---|
| ACPI 补丁 | `Name(_S3)` → `Name(XS3)`（Find `085F53335F`，DSDT，Count 1） |
| SSDT | `SSDT-DEEPIDLE.aml`（`\_SB.LPS0` / `\_GPE.LXEN` 返回 1） |
| Kext | `S0ixStandby 0.5.4` |
| 移除 | `-wex-tgl-edp-softsleep` |
| 电源 | 电池 |

**结果**：✅ 首次 `Wake from Deep Idle`，WakeTime 18.5 秒；但唤醒后**黑屏只剩光标**（WindowServer 超时）。

### 阶段 4：排除轮询进程（用户提示）

停用 mifslidd / mifskeysd / brightlogd（三者都带 100–200ms 定时器）后，Deep Idle 才稳定进入。
**结论**：100ms 级定时器会阻止 CPU 深度空闲。

### 阶段 5：逐个变量实验（2026-11-20）

| # | 变量 | 结果 |
|---|---|---|
| 1 | 移除 `-vi2c-force-polling` | ❌ 唤醒仍 panic（延迟是结果不是原因） |
| 2 | 移除 `-disablegfxfirmware` | ❌❌ **加速失效 + 颜色异常**（必须保留） |
| 3 | `_PSR` 固定返回电池（ADPX3） | ✅ **首个干净 Deep Idle 周期（110 秒）**，但唤醒 WindowServer 挂死 |
| 4 | 加回 `-wex-tgl-edp-softsleep` | ❌ 睡眠根本进不去，直接 forcewake panic |

### 阶段 6：修正版 DMC（2026-11-20 晚）

依据 @Aqpcet 修正的 MMIO 表 + @macintelk 指出的 `fixup_dmc_evt`：

| 项目 | 错误版 | 修正版 |
|---|---|---|
| MMIO 数据 | 全 0 | 固件真实值（9 条） |
| VBLANK fixup | 无 | `0x32` → `0x2e`（DELAYED） |
| 回读校验 | 无 | 9/9 通过 |

**结果**：DMC 加载全部验证通过（`MmioVerified = 9`），但**唤醒问题依旧**（与 @Aqpcet 同 CPU 结论一致）。

## 六、两条死路

| 路径 | 睡眠 | 唤醒 |
|---|---|---|
| **无 softsleep + Deep Idle** | ✅ 能睡（110 秒） | ❌ WindowServer 挂死 → watchdog panic |
| **有 softsleep** | ❌ 睡不进去 | ❌ forcewake panic |

**根因都在 WEX 0.8.3 的 GPU 电源/唤醒路径**：
- 唤醒时 `WindowServer` 30 秒超时
- `AppleIntelMEClientController` / `VoodooI2CHIDDevice` 12–18 秒延迟
- 随后 `SafeForceWake` 在 RENDER 域超时 → panic

## 八、未解问题（给上游的线索）

1. **能否让 WEX 在 Deep Idle 唤醒时跳过完整 modeset？**
   目前不跳 → WindowServer 等不到显示 → 30 秒超时 → 2 次崩溃 → watchdog panic。
2. **能否让 softsleep 不影响 Deep Idle 进入？**
   目前二者互斥：有 softsleep 时系统睡不下去（forcewake panic 在睡眠阶段）。

   已尝试在 `systemDidWake` 重载（修正版），无改善。
