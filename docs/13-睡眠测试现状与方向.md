## 二、当前的失败点：唤醒

### 现象（用户描述）

- 唤醒后**只能看到鼠标**，晃动时没有放大动画而是直接消失
- 之后一片全黑

### 日志证据

## 五、重要认识

1. **睡眠不是"不可用"，而是"能睡不能醒"** —— 这次证明 Deep Idle 能进能出（只是显示栈恢复失败）
2. **softsleep 是显示睡眠的必需品，但可能是系统睡眠的阻碍** —— 需要区分两条路径：
   - 显示睡眠（displaysleep）：需要 softsleep（partial modeset）
   - 系统睡眠（Deep Idle）：可能需要完整 retrain
3. **轮询进程必须全部停**才能进 Deep Idle（这点用户提醒得对）
4. **Fn 亮度键不依赖守护进程**（走 EC + BrightnessKeys 内核层），所以"还能调亮度"不代表守护进程没停

## 六·五、后续两轮实验（2026-11-20）

### 实验 1：移除 `-vi2c-force-polling`

| 项目 | 结果 |
|---|---|
| 目的 | 上次唤醒日志有 `VoodooI2CHIDDevice slow 18400 ms`，怀疑是该参数强制 I2C 轮询 |
| 结果 | ❌ **无效**：睡眠成功进入（`Entering Sleep ... Using Batt 81%`），唤醒仍 panic |
| panic | 仍是 `SafeForceWake acknowledgement never received on RENDER domain` |

**结论**：`-vi2c-force-polling` 不是唤醒失败的元凶（延迟是结果不是原因）。

### 实验 2：移除 `-disablegfxfirmware`

| 项目 | 结果 |
|---|---|
| 依据 | issue #176 说该参数让 GT 一直跑 RP0；GuC 可能参与唤醒上下文恢复 |
| 结果 | ❌ **严重副作用**：**加速失效、颜色异常**（无 Metal） |
| 结论 | `-disablegfxfirmware` 在本机**必须保留**，移除会让图形栈崩溃 |

### 恢复过程与一个坑

恢复时发现 **boot-args 没有真正写入启动用的 ESP**：
脚本用"第一个 209.7MB EFI"匹配，结果改到了别的挂载点。
最终**显式指定 `disk2s1` 并读回确认**才生效。

**教训**：修改 EFI 后必须**读回验证**，不能只看脚本打印。

## 六·六、实验 3/4（2026-11-20 22:30–23:10）

### 实验 3：`_PSR` 固定电池（排除幽灵 AC）

**现象线索**：每次 panic 前日志都出现一次"幽灵 AC"：

```
22:26:44  Entering Sleep ... Using Batt (71%)
22:29:25  Entering Sleep ... Using AC (Charge:0%)   ← 幽灵
22:29:25  Failure during wake → panic
```

**做法**：`SSDT-ADPX` 的 `_PSR` 在 Darwin 下固定返回 0（电池）。

**结果（第一次干净的 Deep Idle 周期）**：

```
22:37:49  Entering Sleep (Batt 69%) 110 secs
22:39:39  Wake from Deep Idle [CDNVA] : due to RTC/Lid Open Using BATT (67%)
```

✅ 无幽灵 AC、无 forcewake panic。

**但新的 panic**：

```
userspace watchdog timeout: no successful checkins from WindowServer
(2 induced crashes) in 120 seconds
```

唤醒日志：

```
Delays to Sleep notifications:
  AppleIntelFramebuffer slow 386 ms
  WindowServer timed out 30000 ms      ← 关键
Delays to Wake notifications:
  AppleIntelMEClientController 12285 ms
  VoodooI2CHIDDevice           12377 ms
```

→ **WindowServer 在唤醒时挂死**，与 @Aqpcet 的"modeset 挂住 GPU"完全一致。

### 实验 4：加回 `-wex-tgl-edp-softsleep`

**假设**：softsleep 的 "partial modeset" 能让 WindowServer 快速恢复。

**结果**：

```
23:04:10  Entering Sleep due to '' Using AC (Charge:0%)
23:04:10  Failure during wake: Informing rootDomain's clients about state changes panic
```

❌ 睡眠**根本没进去**就 panic（forcewake）。
→ **softsleep 与 Deep Idle 互斥**：有 softsleep 时系统睡不下去。

### 总结：两条路都被堵死

| 路径 | 睡眠 | 唤醒 |
|---|---|---|
| 无 softsleep + Deep Idle | ✅ 能睡（110 秒） | ❌ WindowServer 挂死 → watchdog panic |
| 有 softsleep | ❌ 睡不进去 | ❌ forcewake panic |

**根本原因都在 WEX 0.8.3 的 GPU 电源/唤醒路径**，与 @Aqpcet（同 CPU）结论一致。
