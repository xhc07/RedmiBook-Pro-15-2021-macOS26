# Fn 键总览：两种拦截模式

> 本机的 Fn 键分成三类，处理方式完全不同。本文把「亮度键」和「F6/F7/F8 热键」放在一起对比，
> 因为它们用的是**同一个核心思路**：把 EC 查询 `_Qxx` 改名，再用自建 SSDT 重新定义。

## 一、总表

| 键 | 功能 | EC 查询定义在 | 拦截后的去向 | 需要 kext/守护进程 |
|---|---|---|---|---|
| Fn+F1/F2/F3 | 静音/音量± | —（标准 HID） | 系统直接处理 | ❌ |
| **Fn+F4/F5** | **亮度 ±** | **DSDT** `_Q15/_Q16` | `Notify(DD02, 0x86/0x87)` → `BrightnessKeys`（内核） | ❌ 只需 SSDT |
| **Fn+F6** | 投屏 | **厂商 SSDT #21** `_Q2B` | `Notify(HKEY, 1)` → `MIFSKeys.kext` → `mifskeysd` | ✅ |
| **Fn+F7** | 截图 | **厂商 SSDT #21** `_Q66` | `Notify(HKEY, 2)` → 同上 | ✅ |
| **Fn+F8** | 任务视图 | **厂商 SSDT #21** `_Q08` | `Notify(HKEY, 3)` → 同上 | ✅ |
| Fn+F9 | 触控板开关 | —（EC 硬件） | 硬件直接生效 | ❌ |
| Fn+F10 | 键盘背光 | —（EC 硬件 `KBBL`） | 硬件直接生效 | ❌ |

## 二、共同的核心思路

```
EC 发出查询字节
   ↓
ACPI 执行对应的 _Qxx 方法（可能定义在 DSDT，也可能在厂商 SSDT！）
   ↓
OpenCore ACPI Patch：把原方法改名（XQxx）
   ↓
自建 SSDT 重新定义 _Qxx：先调用原方法，再做我们想做的事
```

**关键差异只有两点**：

| | 亮度（F4/F5） | 热键（F6/F7/F8） |
|---|---|---|
| 原方法位置 | **DSDT** | **厂商 SSDT 第 21 张**（`XMCC1806`） |
| 拦截后做什么 | `Notify` 显示设备 → macOS 内核自带亮度机制 | `Notify` 自建设备 → 我们的 kext → 用户态守护进程 |
| 为什么不同 | 亮度有内核级 API，热键的动作（截图/任务视图）只有用户态 API | |

## 三、亮度键（F4/F5）

### 实现
- ACPI Patch：`_Q15→XQ15`、`_Q16→XQ16`（作用于 DSDT）
- `SSDT-BRTN`：重定义 `_Q15/_Q16`，在 `H_EC` 作用域里先调 `XQxx()`，再
  `Notify(DD02, 0x87/0x86)`
- `BrightnessKeys.kext`（acidanthera）：把 0x86/0x87 转成亮度变化

### 试错摘要（详见 [docs/04 §B](04-失败与成功的尝试.md)）
1. 起初以为 Fn 亮度键走 PS2/HID → 改 VoodooPS2 键码表 → **整个键盘失效**
2. 恢复键盘后，用 HID 抓包确认真实路径：**EC 查询，不经过输入栈**
3. 首次实现只改了 `Notify` 目标 → 部分生效
4. 最终 `SSDT-BRTN` + `BrightnessKeys` → 实测每档 ±128

## 四、热键（F6/F7/F8）

### 实现
- ACPI Patch：`_Q2B→XQ2B`、`_Q66→XQ66`、`_Q08→XQ08`
  （**必须限定** `TableSignature=SSDT`、`OemTableId=XMCC1806`、`Count=1`）
- `SSDT-KEYS`：建 `Device(HKEY)`（`_HID = "MIFS0001"`），三个 `_Qxx` → `Notify(HKEY, 1/2/3)`
- `MIFSKeys.kext`：匹配 HKEY，`message()` 收 ACPI 通知，写 `EventCount/LastEvent`
- `mifskeysd`：用户态守护进程，读属性 → 执行动作（打开显示器设置 / 截图 / Mission Control）

### 试错摘要（详见 [docs/04 §H](04-失败与成功的尝试.md)、[docs/10](10-Fn热键实现计划.md)、[Packages/MIFS](../Packages/MIFS/README.md)）
1. HID 两轮抓取（过滤 + 全量）→ 无事件、无厂商页
2. Windows 下直读 EC RAM `0xFE0B0300`（含按住 10 秒）→ 无变化
3. DSDT 里找 `_Qxx` → 只有电池/盖子 10 个查询
4. 取证官方 OSD → 内核驱动只写注册表，用户态走 WMI
5. 分析 35 张 ACPI 表 → **SSDT #21** 找到 `WMID` + 三个 `_Qxx` → `QV20(1/2/3)`
6. 编码测试 v1（全发 0x87）→ 都变暗，无法区分（**方向搞反**）
7. 编码测试 v2（0x86/0x87 混用）→ 映射确认
8. kext 首次编译缺 `_kmod_info` → 加载失败
9. kext 缺 `registerService()` → 用户态匹配不到
10. `IONameMatch` 用错（`HKEY` 而非 `_HID` 值 `MIFS0001`）→ 匹配失败
11. 全部修正 → **F6/F7/F8 可用**
