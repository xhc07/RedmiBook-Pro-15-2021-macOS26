# 已知问题与处理

## 1. 系统睡眠不可用（最重要）

**现象**：点「睡眠」后屏幕黑，系统看似停止响应；用灯照可见画面（仅背光灭）；
几十秒后自动重启；日志中有 `SafeForceWake` 或 WindowServer 看门狗 panic。

**原因**：驱动层缺陷（详见 [05-睡眠调查](05-睡眠调查.md)），非配置问题。

**处理**：

```bash
sudo pmset -a disablesleep 1 sleep 0 hibernatemode 0 standby 0 powernap 0 tcpkeepalive 0
```

- 不要点「睡眠」
- 不要合盖（合盖会保持运行且发热）
- 长时间离开请关机

## 2. 内置麦克风不可用

**现象**：系统里没有输入设备，或录音全是静音。

**原因**：本机麦克风是 Intel SST 的 DMIC 阵列，需要 DSP 固件与 macOS 的 SOF 栈；
macOS 没有对应驱动（HDA-legacy 与 DSP 在同一控制器上互斥）。

**处理**：用 USB 声卡 / USB 麦克风 / 蓝牙耳机。

## 3. Fn 亮度键偶发无响应

**现象**：按 Fn+F2/F3 有时有效，有时没反应。

**原因**：EC 查询（`_Q15`/`_Q16`）上报时序受 EC 固件控制，`BrightnessKeys` 依赖 ACPI 通知。

**处理**：用菜单栏亮度滑块作为替代；或按两次。

## 4. 电池循环次数显示 -1

**现象**：系统信息里「循环次数」为 -1。

**原因**：固件 `_BIX` 字段返回异常值（真实值可从 Windows 电池报告读到，本机为 3）。

**处理**：忽略；电量与充电状态不受影响。

## 5. panic 后触摸板失效

**现象**：一次 panic/强制断电后，触摸板完全无反应（`VoodooI2CHIDDevice` 实例为 0）。

**原因**：I2C 控制器状态未复位。

**处理**：**完全关机**（不是重启）→ 等 5 秒 → 开机。

## 6. ESP（EFI 分区）挂载失败

**现象**：`Volume on diskXs1 failed to mount`。

**原因**：强制断电导致 FAT32 脏。

**处理**：

```bash
sudo diskutil unmount force diskXs1
sudo fsck_msdos -fy /dev/rdiskXs1
sudo diskutil mount diskXs1
```

## 6.5 开机后亮度被自动调高（2026-11-18 已解决）

### 现象
- 关机前把亮度调低，开机后亮度会**自动跳高**（最多两次），跳到约 0.88
- 手动调回后仍会再跳

### 排查方法
写了一个开机自启的亮度记录器（每 200ms 采样，写 `/var/log/brightness.log`）：

工具在 [Tools/diagnostics/brightlogd](../../Tools/diagnostics/README.md)：

```bash
# 安装（一次性）
sudo cp Tools/diagnostics/brightlogd /usr/local/bin/
sudo cp Tools/diagnostics/local.brightlogd.plist /Library/LaunchDaemons/
sudo chown root:wheel /Library/LaunchDaemons/local.brightlogd.plist
sudo launchctl bootstrap system /Library/LaunchDaemons/local.brightlogd.plist

# 查看
cat /var/log/brightness.log
```

日志样例（跳变时）：

```
13:38:13  uptime= 54s  brightness=0.7500   ← 开机初始
13:38:47  uptime= 90s  brightness=0.8799   ← 自动跳高
```

### 根因
NVRAM 里残留了一个旧驱动（nmx / IrisXe）写入的变量：

```
nmintelfb-brightness = 88   （= 0.88，恒定不更新）
backlight-level      = 正常随亮度更新（Apple 的）
```

开机时这个残留值被恢复，覆盖了正确保存的亮度。

### 解决

```bash
sudo nvram -d nmintelfb-brightness
```

删除后重新设置一次亮度（让它以正确值保存），实测**连续两次重启**：

| 次数 | 开机亮度 | 跳变 |
|---|---|---|
| 第 1 次（0.20） | 0.2002 | 无 |
| 第 2 次（0.625） | 0.6250 | 无 |

### 说明

- **改的是 NVRAM（固件变量）**，不是 EFI、不是系统文件、不是驱动
- NVRAM 是非易失存储，**重启和完全关机都保留**，所以修复前后行为在两种启动方式下一致
- OpenCore 菜单里的 "Reset NVRAM" 也会清掉它（副作用是丢失启动项与 boot-args）

## 6.6 `logd` 看门狗超时（开机早期，非致命，2026-11-18 记录）

**现象**：开机时偶发一个崩溃报告 / 弹窗，内容为：

```
logd: WATCHDOG, monitoring timed out for service
unresponsive dispatch queue(s): com.apple.firehose.drain-mem (tid:2006)
40 seconds since last successful checkin（uptime 约 70-80 秒）
displayState: OFF
```

**出现记录**：00:51、02:27、14:35（都是开机早期，uptime 70-80 秒）。

**判断**：**不是 panic，也不影响使用**。`logd` 是系统日志服务，它在开机早期
的日志洪峰中没有及时"签到"，看门狗判定超时并生成报告；系统随后自行恢复。

**可能原因**：

| 猜测 | 依据 |
|---|---|
| 开机日志洪峰 + 外置 USB SSD 写入慢 | 系统装在 USB SSD 上；`firehose.drain-mem` 是日志落盘队列 |
| WhateverXe 启动期日志量大 | 驱动初始化会打不少 IOLog |
| `keepsyms=1` 无法去掉 | SimpleHDA 依赖它，否则音频失效 |

**处理**：**忽略**。若想减少出现频率，可尝试：

- 减少开机日志：不加 `-v`（已做到）
- 换用更快的存储（内置盘不可写，暂不可行）

**状态**：良性，已记录，不做修复。

## 6.7 合盖后显示器不黑屏（2026-11-18 记录，待修）

**现象**：合上笔记本盖子后，**屏幕仍然亮着**（系统没有进入睡眠，显示器也没有关闭）。

**原因**（已确认的部分）：

```
pmset: SleepDisabled = 1              ← 我们主动禁用了系统睡眠（本机睡眠不可用）
ioreg: AppleClamshellCausesSleep = No  ← 系统因此不会因合盖而睡眠
```

本机系统睡眠在驱动层不可用（见 [docs/05](05-睡眠调查.md)），所以 `SleepDisabled=1` 是必须的。
但这也导致 macOS 不再走"合盖 → 关屏"的默认路径。

**修复思路（下次做）**：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 用户态守护进程**（推荐） | 监听 `AppleClamshellState`，合盖 → `pmset displaysleepnow`；开盖 → `caffeinate -u -t 1` 唤醒 | 不动内核、可随时停 | 需要 1 个后台进程（可复用 MIFS 的模式） |
| B. ACPI 层 | SSDT 拦截 `_LID` / EC 盖子查询，合盖时 `Notify(DD02, ...)` 或直接关背光 | 零进程 | 需确认盖子事件走哪条路径；可能与电池/EC 补丁冲突 |
| C. 修改 `AppleClamshellCausesSleep` | 强制设为 Yes | 最直接 | 会导致系统尝试睡眠 → 触发已知的睡眠 panic，**不可行** |

**下次需要先做的验证**：

1. 合盖时 `ioreg -l | grep AppleClamshellState` 是否变成 `Yes`
2. 是否有 `AppleClamshellState` 的 IOKit 通知（还是必须轮询）
3. 合盖时 EC 是否发 `_Qxx`（可用 `fnprobe.sh` 观察）

**状态**：已记录，待修。

## 6.9 外接显示器热插拔后 WindowServer 卡死（2026-11-18 记录，待排查）

**现象**：连接外接显示器后**拔出**，系统卡死（画面冻结，约 40 秒后看门狗介入）。

**证据**（`WindowServer-2026-11-18-150030.ips`）：

```
WindowServer: WATCHDOG, monitoring timed out for service
unresponsive work processor(s): WindowServer main thread
40 seconds since last successful checkin
displayState: OFF
uptime: 760 秒
```

- 同时间段 `logd` 也卡（`com.apple.firehose.io-wl`），所以**内核日志丢失**，无法定位驱动内部
- WindowServer 线程全部 `TH_WAIT/TH_UNINT` → 阻塞在系统调用（驱动）里
- 时间点与"插拔外接屏"高度吻合

**初步判断**：外接屏热插拔触发的 framebuffer/显示管道路径在 WhateverXe 0.8.3 + 本机 eDP 补丁组合下可能死锁。

**下次复现时要收集**：

```bash
# 卡死前开一个终端跑（或另一台机器 SSH）
sudo log stream --predicate 'process == "kernel"' --level debug > /tmp/kernel.log
# 然后插拔外接屏
```

以及：

- 是否每次必现，还是偶发
- 插上时是否正常（只是拔出时卡）
- `ioreg -l | grep -i "IODisplay\|framebuffer"` 在插/拔前后的变化
- WEX 是否已更新版本修复（关注上游 issue）

**临时规避**：

- 尽量在**显示器睡眠/系统空闲**时插拔
- 或先 `pmset displaysleepnow` 再插拔
- 出现卡死时等待看门狗（约 40-60 秒）或强制重启

## 6.10 外接屏 HDR 大概率崩溃（驱动限制，暂无法解决）

**现象**：在外接显示器上开启 **HDR** 后，系统大概率崩溃/卡死。

**判断**：属于 **WhateverXe 驱动层限制**（HDR 需要 10/12-bit 输出 + HDR metadata 路径，
当前 Intel 转译驱动未完整实现），本仓库层面无法修复。

**建议**：
- 外接屏保持在 **SDR** 模式使用
- 如需 HDR，等上游驱动支持（关注 WhateverXe 更新）

**状态**：已知限制，不修。

## 6.11 外接屏（HDMI / Type-C）没有声音（2026-11-18 查清：驱动未实现）

**现象**：接上 HDMI 或 Type-C 显示器后，系统里**没有 HDMI/DP 音频输出设备**，无声音。

### 实测数据（2026-11-18，Type-C 接 4K@60Hz 显示器）

| 检查项 | 实测 | 正常应为 |
|---|---|---|
| 显示器识别 | ✅ 3840×2160@60Hz，`Connection Type: Thunderbolt/DisplayPort` | — |
| framebuffer 端口 | `port-number = 3`，`connector-type = 0x00040000`（DP） | ✅ 正确 |
| `hda-gfx` | `onboard-1`（iGPU 与 HDA 两侧一致） | ✅ 正确 |
| `AppleHDAController` | 1 个，已加载 | ✅ |
| **`IOHDACodecDevice`** | **1**（只有模拟声卡） | **2**（模拟 + 显示音频） |
| **`AppleHDAHDMI_DPDriver`** | **0** | ≥1 |
| **`AppleHDAEngineOutputDP`** | **0** | ≥1 |
| 系统音频设备 | 只有「内建麦克风 / 内建输出」 | 应有 HDMI/DP 输出 |

### 根因：WhateverXe 没有实现显示音频

- 源码里 **没有任何显示音频实现**（`audio` 只出现在 2 处注释，无 HDA / Audio InfoFrame / ELD 相关代码）
- 因此 GPU 侧的音频 codec 从未被使能 → `IOHDACodecDevice` 一直是 1
- 这是 **驱动功能缺失**，不是配置问题；改 `hda-gfx`、connector-type、AppleALC layout 都无效

显示音频需要驱动实现：

1. 使能 GPU 的音频 codec（HDMI/DP audio enable）
2. 写 **Audio InfoFrame**（声道/采样率）
3. 通过 DPCD / AUX 读 **ELD**（显示器音频能力）
4. 与 `AppleHDAController` 完成 codec 枚举握手

### 结论

- **本仓库层面无法修复**（需要改 WhateverXe 内核驱动）
- 属于上游功能缺失，可作为 **feature request** 提交给 WhateverXe
- 临时方案：外接屏用显示器自带的 3.5mm 输出/USB 音箱，或继续用内置扬声器

**状态**：已查清，驱动限制，不修（可报上游）。

## 7. 亮度最低仍偏暗 / 偏亮

**处理**：改 `Patches/ours/` 里的 `floor = hw / 16`（6.25%），例如改为 `hw / 12`（约 8.3%），
重新编译 kext。

## 8. 风扇转速不可控

**现象**：没有风扇转速显示，也无法手动调速。

**原因**：`SMCProcessor` 提供温度，但本机 EC 的风扇控制未实现。

**处理**：暂无法解决；可用第三方工具读温度。

## 9. 外置 USB SSD 启动的额外注意

- 睡眠问题更明显（USB 控制器挂起/恢复）
- 强制断电后 ESP 更容易脏（见 §6）
- 建议定期备份 EFI（本仓库的 `EFI/` 即可作为备份）

## 10. 升级 macOS 前请三思

- 本配置针对 macOS 26.7.3（25G342）验证
- 大版本升级可能改变 kext 依赖（尤其 `SimpleHDA`、`WhateverXe`）
- 升级前请备份 EFI 与 AuxKC：

```bash
sudo cp -R /Library/Extensions/AppleIntelTGLCompat.kext ~/Desktop/
sudo cp /Library/KernelCollections/AuxiliaryKernelExtensions.kc ~/Desktop/
```
