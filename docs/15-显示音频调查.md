# 外接屏显示音频调查（HDMI / DisplayPort）

> **本文由 AI（DeepSeek 辅助）整理，机器为单台孤立测试，结论仅代表本机。**
> 记录时间：2026-11-18 ~ 2026-11-21

## 一、问题

RedmiBook Pro 15 2021（i5-11300H / Iris Xe 9A49）外接 4K 显示器（Type-C → DP）时：

- 画面正常（3840×2160@60Hz）
- **系统里没有 HDMI/DP 音频输出设备**，显示器不出声

## 二、显示音频的正常链路（5 步）

```
① GPU 使能音频
   AUDIO_PIN_BUF_CTL(0x48414) bit31 = 1
   → 唤醒显示 codec：HSW_AUD_CHICKENBIT(0x65F10) bit15 脉冲
   → 校验 codec：AUDIO_CODEC_ID(0x65020) = 供应商(16bit) + 型号(16bit)

② GPU 读显示器能力（ELD）
   DPCD/AUX 读显示器音频能力
   → 写 AUD_PIN_ELD_CP_VLD(0x650C0)：ELD 有效位 + 音频输出使能

③ HDA 控制器枚举 codec
   AppleHDA/SimpleHDA 读 STATESTS → 发现显示 codec → 发 verb → codec 应答
   → 生成 IOHDACodecDevice（显示音频）

④ 创建音频引擎
   AppleHDAHDMI_DPDriver + AppleHDAEngineOutputDP
   → 系统出现「HDMI/DP 输出」

⑤ 每次 modeset 写 Audio InfoFrame（声道/采样率/格式）
```

## 四、实测寄存器（2026-11-21 00:10，外接 4K DP 在线）

采集方式：`MIFSAudioProbe.kext` 放入 EFI，开机时匹配 iGPU（`8086:9A49`）后**只读** dump；
`IOMatchCategory = MIFSAudioProbe`（不抢占其他驱动的匹配位）。

| 寄存器 | 值 | 含义 | 判断 |
|---|---|---|---|
| `0x65020` AUDIO_CODEC_ID | **0x80862812** | Intel(8086) + codec 2812 | ✅ codec 硬件存在 |
| `0x65900` AUD_FREQ_CNTRL | **0x8010** | 8T / PULLCLKS=0 / BCLK_96M | ✅ **正常值**（非坏值 0x901） |
| `0x65F10` HSW_AUD_CHICKENBIT | **0x00000000** | bit15 = codec wake override | ❌ **未唤醒 codec** |
| `0x650C0` AUD_PIN_ELD_CP_VLD | **0x00000000** | ELD 有效 + 音频输出使能 | ❌ **ELD 无效、输出未使能** |
| `0x48414` AUDIO_PIN_BUF_CTL | 0xB00A7077 | bit31 = 1（音频使能） | ✅ 端口层面已开 |
| `0x45400` PWR_WELL_CTL1 | **0x55** | 电源井请求/状态位 | ✅ 已上电 |
| `0x45404` PWR_WELL_CTL2 | **0xFF** | 全部电源井 | ✅ 已上电 |

### 系统侧对照

| 检查项 | 实测 |
|---|---|
| `IOHDACodecDevice` | **1**（仅 ALC256 模拟） |
| `AppleHDAHDMI_DPDriver` 实例 | **0** |

| 系统音频输出 | 只有「内建输出」 |

## 五、根因链

```
WEX 未实现显示音频使能序列
   ↓
0x65F10 bit15 从未置位 → 显示 codec 未唤醒
   ↓
0x650C0 保持 0 → ELD 无效、音频输出未使能
   ↓
HDA 链路看不到该 codec → AppleHDA/SimpleHDA 无法枚举
   ↓
无 HDMI/DP codec 设备 → 无音频引擎 → 无输出设备
```

**关键结论**：
- **不是配置问题**（`hda-gfx`/`connector-type`/`av-signal-type` 全对）
- **不是 codec 缺失**（`0x65020` 有 ID）
- **不是频率寄存器问题**（`0x65900 = 0x8010` 本来就对）
- **是 GPU 侧驱动缺少"唤醒 + ELD + 使能 + infoframe"这段代码**

## 六、方向（GPU 侧需要实现的）

| # | 动作 | 寄存器/位置 |
|---|---|---|
| 1 | 唤醒显示 codec | `0x65F10` bit15 脉冲 |
| 2 | 校验 codec | `0x65020` |
| 3 | 读并写 ELD | `0x650C0` + ELD buffer |
| 4 | 使能音频输出 | `0x650C0` enable 位 |
| 5 | 填 `audio-codec-info` | framebuffer 属性（每次热插拔后重填） |
| 6 | 每次 modeset 写 Audio InfoFrame | InfoFrame 寄存器 |

## 十一、复现方法

```bash
# 1) 把探测 kext 放进 EFI/OC/Kexts，并在 Kernel.Add 注册（Enabled）
# 2) 外接显示器保持接在开机状态
# 3) 重启
# 4) 读取
ioreg -c MIFSAudioProbe -r -d1 -w0 | grep -E 'AUD_|PWR_WELL|65020|65900'
```

> 探测 kext **只读**，不写任何寄存器；`IOMatchCategory` 独立，不抢占默认匹配位。
